# ADR-0009: Measure savings from models the session actually ran

Status: accepted (2026-07-25)

Supersedes the baseline-resolution decision in [ADR-0008](0008-statusline-savings-and-segments.md).
The rest of that ADR — self-silencing segments, the configurable segment list, the "counterfactual,
not a bill" framing — still stands.

## Context

ADR-0008 priced the savings counterfactual at `models.complex`: re-price every transcript entry at
the heavy model's rates, subtract actual spend, show the difference. That is only sound when the
session actually ran something cheaper *because* model-switcher put it there.

It was reported from a live install showing:

```
session $90.05 | saved $90.05 (50%)
```

The savings equalled the session cost exactly, and the percentage was exactly 50%. Neither was a
coincidence. That install had `models.complex = fable` (`claude-fable-5`, $10/$50) while the session
itself ran on `claude-opus-5` ($5/$25) — precisely half on every rate. The arithmetic was correct
and the result was meaningless:

```
baseline = 2 x actual  =>  saved = baseline - actual = actual  =>  saved / baseline = 50%
```

Inspecting the transcript settled it: 253 assistant messages, all `claude-opus-5`. Not one prompt
had ever been delegated. The tool reported saving $90 on a session where it had done nothing at all.

The general fault: `models.complex` is a *statement of intent*, not an observation. Any session
whose model happens to sit at a fixed ratio to the configured heavy model reports a constant
percentage forever, driven by the rate table rather than by any routing decision. The failure is
also silent and flattering — it always overstates, and it looks most impressive exactly when the
router is doing least.

## Decision

- **The baseline is the dearest model the session actually ran on.** Every priced entry is re-priced
  at that model's rates. This is a measurement over the transcript rather than an assertion from
  config, so it cannot describe a counterfactual that was never on the table.
- **Report nothing until a session spans at least two priced models** (`MIN_MODELS_FOR_SAVINGS`).
  One model means nothing was routed, so nothing was saved; showing a number would be inventing one.
  This guard is unconditional and applies to `statusline.savings_baseline` too, so an explicit
  override cannot reintroduce the fabricated figure.
- **Name the yardstick in the output**: `saved $48.00 (40% vs fable-5)` rather than a bare `(40%)`.
  A percentage with no stated denominator invites the reader to supply their own, which is how a
  number generated by a rate ratio passed for a measurement.
- **`resolve_pricing()` returns the pricing key alongside the rates**, so two ids that price
  identically (`claude-sonnet-5` and a dated variant of it) count as one model, not two, when
  deciding whether the session genuinely spanned tiers.
- Alias resolution from `models.complex` is **removed** from this path, along with the
  shortest-key heuristic ADR-0008 introduced to make it safe. Nothing else used it.

## Consequences

- Savings under-report rather than over-report. A session that is entirely cheap-model work shows
  no saving even though running it on the heavy model would genuinely have cost more. That is the
  correct direction for a number the tool computes about itself: an absent figure is recoverable,
  a flattering one is not.
- Verified on real transcripts. The reported session went from `saved $92.64 (50%)` to no savings
  segment, with session cost unchanged at `$92.64`. A separate 570-message session that genuinely
  mixed `claude-opus-4-8` and `claude-fable-5` reported `saved $5.51 (3% vs fable-5)` both before
  and after — where the counterfactual was real, the figure did not move. Only the fabricated case
  disappeared.
- The percentage now varies with how much of a session was delegated, so it moves during a session
  instead of sitting at a constant determined by the rate table. That is the intended signal.
- `TestSavingsCannotBeFabricated` asserts the specific shape of this bug: for a single-model session
  priced against a `models.complex` that is exactly 2x, `saved` must not equal session cost. The
  original assertion (`saved $48.00 (80%)` from a single-model transcript) encoded the bug as
  expected behaviour, which is why the test suite was green throughout.
- A model with no configured rate cannot serve as the second tier — an unpriced model is not
  evidence of routing, and counting it would let `no rate:` sessions resurrect the invented figure.
